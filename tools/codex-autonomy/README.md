# Shared Codex autonomy environment

Portable source for Issue #1952. Requires the existing authenticated Codex installation, Node.js 22+, Python 3.11+ for standard-library TOML validation, and Git. Does not install a scheduler, model API, new account, credential or spending route. Configuration/hook schemas were checked for CLI 0.152.0 and desktop-bundled CLI 0.171.0-alpha.13.2. Real model sessions passed on the desktop runtime. On the audited host, the older npm CLI rejected the configured GPT-6.1-Sol model; use the existing desktop-bundled executable rather than changing model/provider or enabling a paid fallback. See the task evidence for actual host/session results; Windows test success is not Mac hardware evidence.

From this directory on either host:

```text
node --test *.test.mjs
node install.mjs install
```

The installer uses CODEX_HOME or the OS user's `.codex`. It backs up every changed file before changing user settings, preserves unrelated configuration and permissions, merges one owned guidance block and hook groups, installs three standalone roles and one automatically discoverable skill. A pre-existing global override or inline hook source requires reconciliation because it can shadow/duplicate the shared setup. The native child cap is a hardware-derived ceiling; actual admission also considers current memory/load, available quota, dependencies and tighter project limits. `max_depth=1` bounds V1 nested spawning; V2 ignores it, so worker briefs also prohibit recursive spawning.

After installation, use normal Codex **Review hooks / Allow selected** or CLI `/hooks` for the six `Autonomy:` handlers. Do not trust unrelated hooks as part of this setup. No native trust records are generated by the installer. The hook command includes the controller source hash; each installer update changes the definition and requires review. The controller checks the hash before executing policy. Future new sessions load the shared rules automatically. Existing sessions retain their old injected instructions until a fresh session or supported reload.

Hook behavior is opt-in: a recognized development request binds its current session to existing canonical state or a source-hashed read-only projection. Ordinary questions, pause/cancel, approval/resource stops and interrupts allow stopping. No raw prompt, assistant text or transcript is audited. Source/task/evidence hashes, event timestamps and reason codes are local metadata. See `state-contract.md`. This does not prove semantic correctness or enforce total token spending: native account limits, project gates and actual verifier evidence remain required.

Hook JSON input is bounded to one MiB of UTF-8. Malformed, incomplete or over-budget input stops that native request instead of proceeding with unconfirmed owner control. An ordinary user prompt also stops if its disarm signal cannot be persisted. Successfully persisted controls remain effective under lock contention; Interrupt cannot prevent native interruption. Unparseable input has no trustworthy session identity, so it does not invent or modify a binding. The next valid ordinary prompt disarms any earlier binding.

The install command prints a private backup path. Review differences locally, without uploading that backup or credentials. Exact restoration:

```text
node install.mjs restore --backup <printed-backup-path>
```

Restore validates all installed hashes before changing any file; concurrent user/app edits require manual diff review instead of overwriting them. Old permissions and bytes return exactly, newly created owned files are removed, unrelated files remain. Runtime audit files are retained for evidence. Never synchronize an entire CODEX_HOME between devices: install only this versioned portable source on each device, with its own host config, paths, login and hook trust.

Updates: pull the reviewed task revision, run its tests, inspect `git diff`, reinstall and review changed hooks. Existing GitHub/project requirements, state, evidence and handoff mechanisms remain authoritative. The legacy default Compass in the audited ZBook points at another stopped Goal and is deliberately untouched. Heavy tests/builds should reuse the repository's existing resource-admission lane.
