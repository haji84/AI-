# Reverse requirement traceability (#1205)

Repository and runtime audit of JARVIS production-capable surfaces. The index binds each file's bytes to canonical requirement parents or a sourced exclusion. A parent link says what behavior owns the implementation, not that the behavior is complete, connected, secure or physically verified.

Coverage: src/jarvis, src/gai, src/app/jarvis, src/app/api/jarvis, scripts/jarvis*, Android main sources/config, iOS Worker, docs/architecture, src/orchestrator, src/compass, command and owner-auth API routes/entry primitives. Colocated tests are excluded. This is the explicit audit boundary, not a claim that every repository file or unmerged branch has been classified. Provider/media and other application entry surfaces outside these roots still require explicit audit; this report is not whole-repository completion.

Every new/changed/removed surface inside that boundary must reconcile its exact index entry. Run node scripts/jarvis-requirement-audit.mjs --check. The ordinary node --test suite invokes the same validator, so existing CI detects missing/stale mappings without workflow permission changes. There is intentionally no blind re-baseline command.

Accepted owner decisions have explicit source and history. IDEA/PROPOSED do not authorize implementation; ACCEPTED_REQUIREMENT without SPEC_SYNCED fails the repository gate. Synced decisions bind both canonical documents and their requirement definition fingerprints. Supersede links must be reciprocal and acyclic; old decisions remain. IMPLEMENTED/VERIFIED cannot exceed canonical status/evidence. Protected changes always leave this automatic contract for a separate Human Gate.

Trust boundary: these records are reviewed repository artifacts supplied by the owner/Codex workflow. A source URL/hash is provenance, not cryptographic proof of owner identity. Web/PDF/tool content cannot populate accepted records as authority. No network lookup, model-generated permission, automatic physical promotion, or production config edit occurs here.

The checker is wired into repository CI. Broker /api/jarvis/admin/work now consumes the already-read HTTP body once, authenticates through the existing owner token boundary, persists adopted requirement receipts before Goal mutation, and binds the receipt to the authoritative Goal. Retry keys bind exact payloads; unknown authority fields are rejected. Explicit structured adoption or a narrow unambiguous specification declaration creates ACCEPTED_REQUIREMENT; questions/examples remain IDEA and ordinary potential features remain PROPOSED. Broad free-form adoption and coreference extraction still require a bounded Work/Codex review; lexical similarity only ranks candidates.

The existing Compass active envelope stores at most 500 receipts, never silently evicts them, and retains reciprocal correction/withdrawal history. A dedicated transactional update writes receipts; generic worker/model state writes retain the current authoritative envelope. Invalid lifecycle, missing history, cross-Goal correction or broken state fails closed. No schema change. Before execution can report Goal completion, the Goal Loop and Compass write-back revalidate exact local canonical receipts; WorkState evaluation and Work Run progress also show an unsynced block. Explicit planner supersession cannot bypass this gate. A canonical rollback reopens the gap.

Authenticated POST /api/jarvis/admin/requirements/proposal consumes a saved receipt plus explicit reviewed existing-ID bindings/base fingerprints. It produces three reviewable file candidates (ledger, mirror, adopted source history), checks canonical parity, preserves status/evidence/IDs, and refuses stale bases, verified-row amendments and new-ID changes. Corrections/withdrawals reconcile only stored authenticated history, preserve reciprocal links and canonical requirement rows, and remove only exact previous owner additions. Changed prior text fails for conflict review. This is a proposal artifact, not a PR or a canonical write; it cannot set runtime specSynced from a request flag or authorize merge/deploy. Accepted unsynced decisions stay blocked until the actual deployed canonical artifacts contain matching source/provenance/history. Ordinary completion receipts are insufficient.

Remaining #1205 software: free-form semantic/coreference conflict resolution, reviewed new-ID allocation and wider semantic conflict reconciliation, additional entry routes, owner-visible proposal workflow, and remaining audit roots. The generic PR capability remains at three complete files / 100000 bytes; the typed publisher below cannot accept arbitrary files. Do not claim automatic conversation-to-merged-spec completion.

Research Ops remains a separate #321 track. Earlier Creator Studio architecture documents are retained as historical/separate product records, not silently deleted. Legacy Commander/Mac scripts are mapped as compatibility surfaces; a mapping does not attest that they meet current security/operations acceptance.

## Bounded typed publication (#1205)

POST /api/jarvis/admin/requirements/publish (Broker owner token) and /api/jarvis/requirements (existing owner cookie) accept only a saved decisionId and explicit reviewed existing-ID fingerprints/source issue. The generator produces exactly the three canonical files; request-supplied paths, content, tokens and endpoints are rejected. Existing GITHUB_TOKEN is optional capability: unavailable authorization fails visibly (503), never creates/configures credentials. A missing canonical file on current main blocks publication until the candidate contract is deployed.

Bounds: review32KiB; generated output2MiB; changed-line multiplicity budget100000bytes;24fixed-host GitHub requests;45s operation,5s per fetch/body,2MiB response. Requests use api.github.com/repos/haji84/AI- only, reject redirects and scan generated content for known secret patterns before egress (not a guarantee against every possible secret). Trees always retain base_tree; no main/ref update, force push, merge, deployment or automatic reviewer approval. Draft-only publication does not clear the canonical completion gate.

Protected Compass receipt metadata preserves immutable base/artifact/review/branch and optional head/PR identity. Lost responses resume a deterministic branch/commit; unrelated main advance retains original base while current canonical contents are still checked. Changed canonical content, superseded receipt, foreign branch or closed/altered PR fails visibly. Source issue closure after a saved attempt does not prevent reconciliation. A deadline cancels stalled bodies. Broker and browser paths remain owner-authenticated; error messages omit upstream bodies and credentials.
