## Approach

Reuse the existing, unchanged native capture and trusted PowerShell/Node helpers. A separate manual workflow pins the old helpers and new metadata reader to exact SHA256 values, verifies current protected main and all four jobs of the latest matching CI run, and binds the first workflow run and its first attempt to owner haji84 and runner21/ZBook. After source verification it rechecks the same CI identity/attempt and current main immediately before acquisition. A separate PowerShell adapter stages the new query at the capture's existing fixed query leaf and stages the existing bounded JSON helper at its existing allowed leaf. No additional staging name or native capability is introduced.

The Node query opens only the disposable `work/compass.sqlite` with readOnly/query_only, validates physical paths, sidecars, SQLite schema, bounded JSON and unique envelopes, and returns a closed flat metadata report. Unfiltered Goal rows must satisfy the singleton contract. Receipt digests, lifecycle and same-Goal provenance links follow the existing intake contract; WorkRuns must satisfy the persisted record contract and unique run identities. It counts stored requirement receipts, receipts linked to the original Goal or unbound, JARVIS name mentions, and all/target WorkRuns. It may report the derived current Goal ID and a boolean JARVIS name match. Plaintext titles, statements, IDs of individual receipts, paths and credentials never enter public output.

This is the implementer's choice within the owner's continuing investigation instruction. A public-site-only approach has no reachable deployment; an in-place application store or constructor would risk writes/migrations. The established protected copy is the useful bounded alternative.
