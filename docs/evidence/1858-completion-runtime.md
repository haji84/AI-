# #1858 常用接続準備・検証記録

## 対象と承認

Ownerの2026-10-23「常用環境への有効化と実運用受入まで進めて」に基づく、Issue1858限定の継続工程。PR1860/main `fcd9e0e6e9127760340d0ed710187428f2b6c0f8` の接続機能を再利用する。Remote Lite1831/1832、正式Goal681/1219、認証・権限・保護規則は変更しない。

新規の常用アダプターは、Work/Codexが作成しホスト設定のSHA256で固定した有限の指示だけを読む。Goal全体のdigest、Goal ID、実行revision、対象root、期限を照合し、毎回再検証する。読み込めない指示を別モデルへ回す処理はない。初期能力は `context.inspect` のみ。既存開発経路の包括的な置き換えや、任意の自然言語からの自動依存関係抽出は未達。

## 実行証拠

- 新規テストは実装前に失敗を確認。ホスト指示→実際のCompass adapter→SQLite→ファイル読戻し、再起動、改変拒否を検証。
- 実際の `jarvis-goal-executor.ts` 子プロセスで、development intentがあっても固定指示を先に検証。改変時はexit1・WorkRun BLOCKED。
- 実際のBrokerをloopbackの動的ポートで起動。起動時のWorkRun復帰→子実行子→所有者認証付きHTTP→COMPLETEDと証拠を確認。再起動後は同じcycle IDで二重実行なし。認証なしは401。
- ファイル検査と実機条件を同一criterionに課し、ファイルだけではgoal_completeにならないことを確認。要件は自動的にファイル検査へ縮約しない。手渡し指示の作成者は元の条件を漏らさず契約化する必要がある。
- 独立レビューで「検査失敗でも実行済みにし再検証できない」問題を発見。誤ったバイト列→修正→再起動のREDを確認し、負の独立証拠がある作業をcompletedTasksへ追加しない修正でGREEN。
- 対象・関連試験51件 PASS/0 FAIL/0 SKIP。新規ファイル7件を含む。型検査・CI・最終レビューの結果はIssue/PR保存点で追記する。

これは同一Windows上の隔離DB・合成Goal・ローカルファイルによる受入。常用Goalでの自律開発成功、実機遠隔操作、配布可を意味しない。

2. 所有者Windowsセッションで、対象プロセスのPID・生成時刻・実行パス・親PIDと既存taskを照合する。権限変更が必要なら具体的な補助処理を提示しHuman Gateへ戻す。
