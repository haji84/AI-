## Failure and recovery

Windows journals the exact baseline and proposed ACL before mutation and reports UNCERTAIN after an unconfirmed mutation. Rollback verifies the exact resulting state and removes only the recorded NIC/direction/weight rule, preserving all previous entries. It requires the original plan still to be fresh and unexpired; outside that window a new reviewed recovery authorization is required. A truncated host journal also stops for reconciliation; automatic recovery is not claimed for that case. Existing ACL cmdlets have no compare-and-swap: one authorized Hyper-V writer and owner-controlled authority directories are prerequisites. Guest application likewise requires a single authorized administrative writer. Do not claim atomicity against a simultaneous external administrator.

Ubuntu records intent before account/config changes, keeps a private original-config backup, and attempts restoration on failure. A trailing interrupted journal append is recoverable from committed records, retaining the discarded fragment's size/hash; malformed complete/interior records refuse. A valid owned gate is revoked before refusing concurrent main-config drift. Unrelated administrator changes are never overwritten. Existing sessions are not terminated; `sessionsTerminated:false` remains explicit. If an account/policy/file no longer matches or connections prevent shell restoration, retain the journal and revoked gate and report incomplete rollback. Retrying recovery does not delete previous evidence.

Reverting the source change is not an operational rollback for an already activated connection. A future real activation must retain its exact installer version, original state, receipt and journal until its restoration has been verified.
