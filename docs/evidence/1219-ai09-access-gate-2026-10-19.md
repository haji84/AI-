## Automated baseline collection

`scripts/ai09-baseline-collector.mjs` now supplies the automated client. `scripts/ai09-baseline-command-gate.sh` supplies the fixed `ai09-baseline-v1` guest verb and preserves the earlier identity/exit7/timeout acceptance verbs. Neither is installed or activated on AI-09. Baseline retrieval is automated once an independently approved authenticated transport exists; the owner is not asked to run or paste a guest collection command.

The safe current-host availability check is:

```text
node scripts/ai09-baseline-collector.mjs
```

With no configuration it exits 1 and returns `{"ok":false,"status":"BLOCKED","code":"AI09_BASELINE_UNCONFIGURED","reason":"AUTHENTICATED_GUEST_TRANSPORT_NOT_PROVISIONED"}` before inspecting a credential or starting a process. This diagnoses missing configured access; it does not claim to have contacted Ubuntu.

The configured form takes exactly an absolute owner-config path and its independently supplied SHA256: `node scripts/ai09-baseline-collector.mjs <OWNER_CONFIG_ABSOLUTE_PATH> <EXPECTED_CONFIG_SHA256>`. It is a network operation and must only be used after the separate access activation is approved and verified. This source work did not invoke it against a real endpoint.

The bounded JSON configuration has exactly these fields:

| Field | Required meaning |
| --- | --- |
| `version` | `1` |
| `host`, `port`, `user` | One freshly verified RFC1918 IPv4 address, TCP `22`, existing account `ai09`; no hostname/DNS lookup, discovery, subnet, alternate port or fallback |
| `expectedHostname`, `expectedMac` | Fresh expected guest identity, independently bound to the VM/NIC |
| `identityFile` | Existing absolute owner-controlled SSH identity path; the collector checks metadata only and never reads its contents; SSH uses it for the approved authentication |
| `knownHostsFile`, `knownHostsSha256` | Existing dedicated owner-controlled file containing exactly one plain endpoint/public-key entry, plus its expected SHA256 |
| `hostKeyFingerprint` | SHA256 public-key fingerprint matching that entry and the guest's public-key observation |
| `sshExecutable` | Existing absolute owner-controlled `ssh`/`ssh.exe` executable; no PATH discovery or installation |

Config, identity, known-hosts and executable paths must be outside the candidate workspace, have no symbolic-link ancestors, and remain owner-controlled throughout the operation. The code validates regular-file metadata and bounded config/public-key reads; it does **not** prove Windows ACL ownership, prevent replacement by the same owner principal, or supply an OS isolation boundary. The independent config digest must come from the approved local control path, not from the guest or an untrusted packet. Do not publish actual private-key paths or credential values.

The client starts one direct SSH process with BatchMode, strict pinned host keys, an explicit null config, no agent, password, keyboard-interactive, PTY, forwarding, proxy, local command, multiplexing or user-provided remote verb. It strips ambient SSH/askpass environment authority. Combined stdout/stderr is capped at 32 KiB and the work deadline is at most 10 seconds. On failure it requests termination, waits at most another 500 ms for close, and detaches streams/process references if close remains unconfirmed. The result retains bounded digests/counts and `closeObserved`; an unconfirmed close is failure, not verified remote cleanup. There are no retries, address probes, installations, service changes or privilege prompts.

The guest verb requires existing non-root `ai09`, runs fixed source in an empty child environment under an eight-second deadline (one-second kill grace), and uses bounded read-only probes. It reports UTC time, hostname, `eth0` MAC/IPv4, `ssh.socket`/`ssh.service` states, exactly ten executable-presence observations, and fingerprints of only the three named **public** SSH host-key files. It never reads a private key, authentication file, token or environment dump. The client rejects missing observations, malformed data, identity/address/fingerprint drift and nonzero remote exit. A missing public-key observation prevents collected status.

The non-root firewall observation is explicitly `readable-policy-not-evaluated`, `permission-or-read-unavailable` or `executable-missing`. Permission denial never means a disabled firewall. Executable presence proves neither a working service nor a container/privilege boundary. Root-only effective sshd/firewall policy remains an activation precondition. The outer guest login/forced-command environment must be secured during activation: this script cannot undo startup hooks already executed by the login shell before it starts.

Verification is local: TDD observed the unimplemented client, omitted-runtime observation, non-22 scope and missing process-detach regressions fail, then pass. The targeted suite uses fake SSH subprocesses for pins, refusal, deadlines, output limits, stream/close behavior and identity validation. The no-config CLI runs real Node locally; syntax and unknown-command rejection run real Git Bash. Those tests are not a real Ubuntu, SSH authentication, firewall, remote-process cleanup or independent Verifier proof.

A fresh host-side read-only baseline must independently bind HAJI, VM `453b139b-cceb-446e-99fb-f45bf5895436`, the current VM name, NIC MAC `00155DDC2C00`, virtual switch, actual host address, VM addresses, OS/seed attachment identity and the complete existing ACL entries/digest. Current tooling cannot read protected Hyper-V state without the needed existing host authority. Do not assume a Runner or previously elevated process is available or authorized for this purpose.
